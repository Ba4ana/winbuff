# winbuff

Набор административных скриптов для подготовки и обслуживания Windows и Debian. Репозиторий содержит **два Windows-загрузчика** и **интерактивный Bash-скрипт**. Это не единый установочный пакет: часть Windows-логики доставляется отдельным архивом и не входит в Git.

**Версия обоих Windows-загрузчиков в исходном коде:** `0.6.6`  
**Целевая версия 7-Zip:** `26.05` (имя установщика — `2605`)

> [!WARNING]
> Скрипты меняют настройки операционной системы, права доступа, конфигурацию сети и запуск программ. Выполняйте их только после просмотра исходников и проверки в тестовой среде. Полного автоматического отката нет.

## Windows: `winbuff.py` и `_winbuff.ps1`

### Требования и рабочие каталоги

- Запуск в Windows с правами, достаточными для изменений `C:\Windows`, `C:\Admins`, реестра, политик PowerShell и задач планировщика (обычно **от имени администратора**).
- Для `winbuff.py` необходимы Python 3 и сторонний пакет `requests`; также используются стандартные модули Python, в том числе `winreg`.
- `_winbuff.ps1` использует Windows PowerShell и штатные средства Windows (включая `Get-WmiObject`, `Expand-Archive`, `schtasks`, `robocopy`).
- Общие рабочие пути: `C:\Windows\_winbuff`, `C:\Windows\_winbuff\temp`, `C:\Windows\_winbuff\log` и `C:\Admins\add`.
- Установщики 7-Zip размещаются **по-разному**: Python использует `C:\Admins\add\components\7zip`, PowerShell — `C:\Admins\add\7zip`.
- Оба загрузчика используют задачу планировщика `_winbuff` и общие рабочие файлы; **не запускайте их одновременно**.

### Что выполняют загрузчики

1. Создают рабочие каталоги и показывают приветствие.
2. Сравнивают установленный 7-Zip с версией `26.05`, при необходимости загружают установщик с `7-zip.org` и запускают его в тихом режиме (`/S`).
3. Скачивают внешний архив `_winbuff.zip` с FTP-сервера, указанного непосредственно в исходниках.
4. Распаковывают архив в `C:\Windows\_winbuff\temp`: Python — через `zipfile`, PowerShell — через `Expand-Archive` с запасным вариантом на COM `Shell.Application`.
5. Копируют `_winbuff.ps1` в основной каталог и синхронизируют `temp\add` с `C:\Admins\add` командой `robocopy /MIR /Z /XO /R:0 /W:5`.
6. Если задача `_winbuff` отсутствует, пытаются создать её из XML-файла, доставленного во внешнем архиве.
7. Меняют ассоциации и команды открытия `.ps1` в реестре, а также политику выполнения PowerShell.
8. Запускают внешний файл `loging.ps1` из временного каталога.

**Различия реализаций:**

| Поведение | `winbuff.py` | `_winbuff.ps1` |
|---|---|---|
| Версия загрузчика / 7-Zip | `0.6.6` / `26.05` | `0.6.6` / `26.05` |
| Проверка сети | TCP к `8.8.8.8:53` | ICMP к `8.8.8.8` |
| Загрузка 7-Zip | `requests` | `System.Net.WebClient` |
| Распаковка | Python `zipfile` | `Expand-Archive` → COM fallback |
| Execution Policy | Запись `Bypass` в HKLM | Установка `Bypass` для Process, CurrentUser, LocalMachine |
| Брандмауэр Windows | Отдельное правило не создаёт | Пытается добавить разрешающее правило `_winbuff` |
| Обработка ошибок | Ряд ошибок перехватывает и продолжает выполнение | Глобально задано `$ErrorActionPreference = 'SilentlyContinue'` |

> [!CAUTION]
> `robocopy /MIR` может удалять файлы в каталоге назначения, отсутствующие в источнике. Запуск чужого или изменённого архива приводит к исполнению полученного из него PowerShell-кода. Не считайте приветственный текст о точке восстановления гарантией: в исходниках загрузчиков её создание не реализовано.

### Границы проверки Windows-установки

Внешние `_winbuff.zip`, `_winbuff.xml` и `loging.ps1` не входят в репозиторий. Содержимое архива, параметры задачи планировщика и итоговые действия `loging.ps1` невозможно надёжно описать или проверить только по данному Git-репозиторию. Наличие файлов на FTP и успешность установки на реальной машине здесь не подтверждаются.

## Linux / Debian: `winbuff.sh`

Интерактивный Bash-скрипт требует **root** (`EUID=0`). Показывает сведения о системе, затем предлагает выбрать действие; `0` завершает работу. Код рассчитан на Debian, но явной проверки дистрибутива при старте нет. Запускать его на другой ОС не следует.

| Пункт | Фактическое действие |
|---:|---|
| `1` | Первичная настройка: APT и базовые пакеты (`sudo`, `curl`, `socat`, `git`, `wget`, `lnav`, `btop`, `mc`, `whois`, `gnupg2`, `ncdu`, `console-cyrillic`), параметры Bash history, `sudo NOPASSWD` для существующего `tech`, глобальное отключение IPv6 через sysctl. |
| `2` | Обновление пакетов (`apt update`, `upgrade`, `dist-upgrade`, очистка). |
| `3` | Установка и настройка `unattended-upgrades`, включая автоматическую перезагрузку в `04:00` и добавление шаблонов origins Proxmox, Docker, Zabbix. |
| `4` | Остановка/отключение `unattended-upgrades`, отключение APT-таймеров, удаление пакета и файлов конфигурации автообновлений. |
| `5` | Установка **Zabbix 7.0 Agent** (пакет `zabbix-agent`, не `zabbix-agent2`) для Debian 12/13; адрес сервера мониторинга закреплён в коде. |
| `6` | Настройка имени интерфейса `eth0`: `net.ifnames=0` в GRUB, DHCP в `/etc/network/interfaces`, перезапуск `networking`; может потребоваться перезагрузка. |
| `7` | Обновление Debian **12 → 13**: обновление пакетов, копии части APT-конфигурации в `/root/upgrade-backup`, отключение сторонних `*.list`, замена `bookworm` на `trixie` в `sources.list`, `full-upgrade`. |
| `8` | Создание пользователя `tech` при отсутствии; при повторном запуске — настройка существующего пользователя, группы `sudo` и `/etc/sudoers.d/tech` с `NOPASSWD:ALL`. |
| `9` | Попытка разрешить **root-вход по SSH в целом**, а не только SFTP: запись `PermitRootLogin yes` и перезапуск `sshd`. |
| `10` | Очистка `~/.bash_history` и истории текущего shell-сеанса. |
| `0` | Выход из меню. |

### Важные ограничения Debian-сценария

- Пункты `1` и `8` предоставляют `tech` возможность выполнять любые команды через `sudo` **без пароля**. Пункт `9` ослабляет ограничения для входа root; его название «SFTP root» не отражает реального масштаба изменения.
- Пункт `1` отключает IPv6 для всей системы. Пункт `3` разрешает автоматическую перезагрузку; пункт `4` отключает также таймеры APT.
- Пункт `6` меняет имя и конфигурацию сетевого интерфейса, немедленно перезапускает сеть и может оборвать удалённое подключение. Не применять без консольного доступа и плана возврата.
- Пункт `7` сохраняет **только часть конфигурации APT**, а не полный backup системы. Скрипт не гарантирует корректную обработку всех источников формата `*.sources`, сторонних репозиториев, зависимостей и последующего отката. Перед upgrade нужны независимый проверенный backup и штатный план миграции.
- Скрипт не является универсально идемпотентным: повторный запуск отдельных пунктов может менять конфигурацию повторно. Успешное завершающее сообщение само по себе не подтверждает результат всех команд.

### Проверка синтаксиса Bash

```bash
bash -n winbuff.sh
```

Это **только синтаксическая** проверка, не безопасный тест системных изменений.

### Статус `cheklist.md`

Это исторический документ, **не инструкция запуска**. Например, в нём указаны BBR/fq и `zabbix-agent2`, тогда как текущий `winbuff.sh` не настраивает BBR/fq и устанавливает `zabbix-agent`. Фактическое поведение определяет исходный скрипт.

## Безопасность и известные риски

> [!IMPORTANT]
> **В публичных исходниках обоих Windows-загрузчиков присутствуют встроенные учётные данные FTP.** По информации владельца, учётная запись имеет права **только на чтение (read-only)** и доступ **только к одному файлу — `_winbuff.zip`**; фактические ограничения на FTP-сервере независимо не проверены. Такой доступ уменьшает возможный ущерб, но пароль опубликован в Git, а обычный FTP не шифрует его при передаче. Рекомендуется сменить опубликованные учётные данные и обеспечить защищённую доставку архива; удаление секрета из актуальных файлов само по себе не очищает историю Git.

- Архив загружается по **обычному FTP без шифрования**, без проверки цифровой подписи или контрольной суммы перед исполнением. Назначение `Tls12` в PowerShell-коде не превращает `ftp://` в FTPS.
- Значительная часть Windows-сценария находится вне репозитория; доверять ему без отдельной проверки содержимого и происхождения нельзя.
- Некоторые ошибки загрузки, установки, копирования и настройки не останавливают последующие шаги; вывод об успехе не всегда основан на проверке кодов возврата.
- `ExecutionPolicy Bypass`, разрешающие правила брандмауэра и изменение ассоциаций PowerShell увеличивают область воздействия загрузчиков.
- В Linux-скрипте жёстко заданы некоторые параметры (включая адрес Zabbix). Изменения SSH, sudo, IPv6, сети и версии Debian требуют индивидуального согласования.

**Приоритеты улучшения:** вынести секреты и конфигурацию из кода; сменить опубликованные FTP-учётные данные с сохранением минимальных прав; перейти на защищённую доставку файлов с проверкой подписи/хеша; завершать установку при критических ошибках; сделать изменения прав и сети опциональными; добавить автоматические проверки Bash, Python и PowerShell и тестирование в изолированной среде.
