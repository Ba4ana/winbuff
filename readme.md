# winbuff

Набор административных утилит для подготовки и обслуживания Windows- и Debian-систем.

**Текущая версия Windows-загрузчиков:** `0.6.4`  
**Версия 7-Zip:** `26.02`  
**Дата проверки репозитория:** 29.07.2026

> [!WARNING]
> Скрипты выполняют системные изменения с повышенными правами. Перед запуском проверьте код, внешний архив и используемые параметры на тестовой машине.

## Состав репозитория

| Файл | Назначение |
|---|---|
| `winbuff.py` | Windows-загрузчик на Python: устанавливает 7-Zip, получает внешний архив, разворачивает файлы и запускает следующую часть установки. |
| `_winbuff.ps1` | Альтернативный Windows-загрузчик для Windows PowerShell. Дополнительно меняет ExecutionPolicy, ассоциации `.ps1` и создаёт правило Windows Firewall. |
| `winbuff.sh` | Интерактивная утилита для первичной настройки и обслуживания Debian. |
| `license.md` | Лицензия MIT. |
| `readme.md` | Документация проекта. |

## Windows

### Назначение

Windows-загрузчики подготавливают каталоги, устанавливают 7-Zip, скачивают `_winbuff.zip`, распаковывают его и запускают дальнейшие сценарии из архива.

Используемые каталоги:

- `C:\Windows\_winbuff` — основной каталог, временные файлы и предполагаемые логи;
- `C:\Admins\add` — дополнительные компоненты;
- `C:\Windows\_winbuff\temp` — загрузка и распаковка архива.

Ожидаемое содержимое внешнего архива:

- `_winbuff.ps1`;
- `_winbuff.xml`;
- `loging.ps1`;
- каталог `add`.

### Зависимости

- Windows с правами локального администратора;
- Windows PowerShell;
- доступ к `7-zip.org`;
- доступ к серверу обновлений `winbuff.evrasia.spb.ru`;
- доступ к `8.8.8.8:53`, который используется для проверки интернета;
- Python 3 и пакет `requests` — только для `winbuff.py`.

Установка зависимости Python:

```powershell
python -m pip install requests
```

### Запуск

Запускать из консоли PowerShell от имени администратора.

PowerShell-вариант:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\_winbuff.ps1
```

Python-вариант:

```powershell
python .\winbuff.py
```

Не запускайте одновременно оба загрузчика: они используют одинаковые каталоги и одну задачу планировщика `_winbuff`.

### Как проверить

```powershell
Get-ScheduledTask -TaskName '_winbuff' -ErrorAction SilentlyContinue |
    Format-List TaskName,State,TaskPath

Get-NetFirewallRule -DisplayName '_winbuff' -ErrorAction SilentlyContinue |
    Format-List DisplayName,Enabled,Direction,Action

Get-ChildItem -LiteralPath "$env:SystemRoot\_winbuff" -Force -ErrorAction SilentlyContinue
Get-ChildItem -LiteralPath 'C:\Admins\add' -Force -ErrorAction SilentlyContinue

& 'C:\Program Files\7-Zip\7z.exe' | Select-Object -First 2
```

### Где логи

В загрузчиках объявлен каталог:

```text
C:\Windows\_winbuff\log
```

Текущий код загрузчиков не гарантирует запись журналов в этот каталог. Дополнительное логирование может находиться во внешнем архиве `_winbuff.zip` и должно проверяться отдельно.

### Как удалить

Удаление задачи, правила Firewall и основного каталога:

```powershell
$TaskName = '_winbuff'
$InstallPath = Join-Path $env:SystemRoot '_winbuff'

Get-ScheduledTask -TaskName $TaskName -ErrorAction SilentlyContinue |
    Unregister-ScheduledTask -Confirm:$false

Get-NetFirewallRule -DisplayName $TaskName -ErrorAction SilentlyContinue |
    Remove-NetFirewallRule

if (Test-Path -LiteralPath $InstallPath) {
    Remove-Item -LiteralPath $InstallPath -Recurse -Force
}
```

Каталог `C:\Admins\add` автоматически не удаляется, так как в нём могут находиться файлы других процедур. Сначала проверьте его содержимое:

```powershell
Get-ChildItem -LiteralPath 'C:\Admins\add' -Force
```

Удаление файлов не восстанавливает прежние значения ExecutionPolicy и изменённые ассоциации `.ps1`: загрузчики не сохраняют исходную конфигурацию.

## Linux

### Назначение

`winbuff.sh` предоставляет интерактивное меню со следующими операциями:

1. первичная настройка, установка пакетов, настройка истории, отключение IPv6;
2. обновление пакетов;
3. установка и настройка `unattended-upgrades` с автоматической перезагрузкой в `04:00`;
4. удаление `unattended-upgrades`;
5. установка Zabbix Agent с сервером `192.168.103.251`;
6. переименование сетевого интерфейса в `eth0` и настройка DHCP;
7. обновление Debian 12 до Debian 13;
8. создание пользователя `tech` с `NOPASSWD`-доступом через sudo;
9. включение `PermitRootLogin yes` для SSH;
10. очистка истории команд.

### Зависимости

- запуск от `root`;
- Debian с `apt` и `systemd`;
- Debian 12 или 13 для операций, где версия проверяется явно;
- сетевой доступ к используемым репозиториям пакетов.

### Запуск

Сначала проверить синтаксис:

```bash
bash -n winbuff.sh
```

Затем запустить:

```bash
chmod 0750 winbuff.sh
./winbuff.sh
```

### Как проверить

Проверки выбираются по выполненному этапу:

```bash
cat /etc/os-release
id tech
systemctl status unattended-upgrades.service --no-pager
systemctl status zabbix-agent.service --no-pager
sshd -T | grep '^permitrootlogin'
ip -br address
```

### Как удалить

Сам `winbuff.sh` не устанавливается как сервис. Для удаления только файла скрипта:

```bash
rm -f -- ./winbuff.sh
```

Изменения, уже применённые выбранными пунктами меню, при удалении файла не отменяются. Для удаления `unattended-upgrades` предусмотрен пункт `4` внутри скрипта. Универсальной процедуры удаления остальных изменений в репозитории нет.

## Критичные файлы и параметры

- `winbuff.py` и `_winbuff.ps1` содержат параметры доступа к FTP непосредственно в исходном коде;
- внешний `_winbuff.zip` не хранится в репозитории, но его содержимое запускается с повышенными правами;
- `_winbuff.ps1` меняет ExecutionPolicy для `Process`, `CurrentUser` и `LocalMachine`;
- `_winbuff.ps1` меняет ассоциации запуска файлов `.ps1`;
- `winbuff.sh` содержит операции обновления ОС, изменения сети, SSH, sudo и удаления истории.

## Риски и известные ограничения

1. **Секреты в репозитории.** FTP-реквизиты необходимо заменить, удалить из кода и считать скомпрометированными. После замены требуется очистить их из истории Git.
2. **Незашифрованный FTP.** Архив передаётся без криптографической защиты и затем запускается с административными правами. Предпочтительно использовать HTTPS/SFTP и обязательную проверку SHA-256 или цифровой подписи.
3. **Внешний код.** Репозиторий не содержит полный набор выполняемых Windows-скриптов, поэтому по нему невозможно полностью проверить итоговые изменения системы.
4. **Точка восстановления.** В приветственном тексте заявлено создание точки восстановления, но в доступных исходниках репозитория эта операция не реализована. Возможное наличие такой логики во внешнем архиве необходимо проверять отдельно.
5. **Частичное выполнение.** Ошибки во многих местах подавляются или не останавливают сценарий, поэтому система может остаться в промежуточном состоянии.
6. **Жёстко заданные параметры.** Версии, адреса, пути, сервер Zabbix и системные настройки записаны непосредственно в коде.
7. **Опасные Linux-операции.** Обновление Debian, перезапуск сети, включение root SSH, `NOPASSWD` и очистка истории требуют отдельного согласования перед эксплуатацией.

## Рекомендации перед эксплуатацией

- заменить и отозвать опубликованные FTP-реквизиты;
- перенести конфигурацию и секреты из кода во внешние защищённые параметры;
- заменить FTP на защищённую доставку с проверкой целостности;
- добавить подтверждения и режим проверки для опасных операций;
- разделить Windows- и Linux-части по отдельным каталогам;
- добавить единый источник версии, журнал изменений и автоматические проверки синтаксиса;
- фиксировать исходные настройки перед их изменением, чтобы удаление было предсказуемым.
